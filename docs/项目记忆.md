## 已知问题与修复记录
- 平台会话竞态问题：客户端正常停止/异常退出后快速重启时，旧连接的 unregister 会无差别删除该设备名下所有会话，导致新连接的打洞 offer 转发失败、中继凭证无法下发，最终回落中继模式。修复方案：register 顶替旧连接时锁内同步作废旧连接的会话；unregister 仅当前连接有权清理设备状态。修复版平台包为 `dist/LiLink-Platform-1.0.4.zip`，需部署到生产服务器 101.126.92.177
- 可靠通道误判死问题：reliable.go 原逻辑以「30s 无确认进展」作为判死依据，会在对端背压、接收缓冲满、应用暂停读取时误杀存活通道。修复方案：判死条件改为「30s 未收到对端任何合法报文」，新增 lastRx 原子时间戳，移除 maxTries 重传超限判死
- 防火墙规则问题：无管理员权限时添加防火墙规则失败，导致跨网打洞无法正常工作。修复方案：fwutil 无权限时自动弹出 UAC 提权窗口执行规则添加（90s 限时）；Inno Setup 安装/卸载时自动添加/删除「LiYou P2P Agent UDP-In」入站规则
- Android 升级降级问题：旧版本硬编码版本号与线性递增 versionCode 导致无法降级安装，修复方案为采用大步长递增 versionCode 覆盖所有历史构建
- Android 升级后打开浏览器问题：Android 11+ 包可见性限制导致安装器无法被隐式 intent 解析，修复方案为在 AndroidManifest.xml 中声明安装器查询规则
- 自启映射未生效问题：开机自启时 agent 启动早于前端事件订阅，导致映射规则标记为未生效但服务实际运行。修复方案：前端轮询检测运行状态时统一补齐生效标记
- HTTPS 隧道兼容性问题：金万维 HTTPS 类型隧道会剥离 WebSocket Upgrade 头，导致信令握手返回 400 失败，当前生产环境统一使用 58894 端口的 HTTP 直射隧道

## 打洞/NAT 关键经验
- NAT 映射必须「热」：STUN 探测后必须立即打洞；映射创建后闲置 1-3 秒会被部分路由器回收/暂停转发（1.0.8 预取 STUN 导致第 2 轮打洞失败回中继，1.0.9 修正为只预取套接字、STUN 留在开打前）
- 平台在设备断线/顶替时必须发 session_close 通知对端立即拆会话（hub.go notifyPeerClosed），否则对端可靠通道空转重传 30 秒且干扰重连
- 客户端测试环境 NAT 为端口保持型单层（公网端口==私网端口），打洞条件理想；打洞目标地址已落日志便于诊断
- 双轮打洞+协同重试机制（punch_offer/punch_result 带 round 标记）消除了重连风暴下的粘性中继
- 打洞预取仅可提前创建套接字，禁止提前执行 STUN 探测，避免 NAT 映射闲置失效
- 中继不再是最终状态：即使首次打洞失败回落中继，客户端会在中继建立后静默重试打洞，打通后原地将连接升级为 P2P 直连，业务子流不中断无需重连；该机制需要客户端和服务端两端同时升级到 1.1.0 版本才能生效
- 移动端蜂窝网络（4G/5G）普遍为对称 CGNAT，UDP 打洞无法实现，必然回落中继，属于正常现象

## 新增实现规则
- 客户端角色应忽略 `device_online` / `device_offline` events from other clients to avoid log spam; server-side may retain these logs for diagnostic purposes
- Windows desktop client auto-start on boot is implemented via HKCU Run registry entry, enabled by default with a user toggle; auto-start launches the app hidden to tray and automatically restores saved login and agent connection without user interaction
- 桌面端内置卡死看门狗：窗口挂起超过 3 秒自动落盘完整 goroutine 堆栈与事件流水到 `C:\ProgramData\LiYouP2P\hang-report.txt` 用于诊断
- Win7 适配采用独立的 `gui-walk` 纯 Win32 薄壳方案，使用 Go 1.20.14 编译（最后支持 Win7 的 Go 版本），复用现有 agent 内核，不修改现有 gui-wails 代码；提供 x86/amd64 双架构绿色包和独立安装器，与主版本 GUI 共享配置文件路径

## Win7 双工具链构建（2026-11-12 实操确认，详见 skills/07-构建Win7版.md）
- 双 Go 工具链并存：`D:\soft\go`=go1.22.12（主构建专用），`D:\soft\go1.20.14`=go1.20.14（仅 Win7 构建）。**严禁解压 1.20 覆盖 D:\soft\go**（混入 1.22 残留会 stdlib 编译错乱；覆盖后须删目录从 zip 干净重解压）
- 一键构建：`scripts/build-win7.ps1` → dist\LiLink-pc-win7-<ver>-x64/x86.zip + installer\dist\LiLink-Setup-Win7-<ver>.exe；exe 名与主包一致（LiYouP2P.exe+liyou-agent.exe），产物已在 1.1.5 验证
- agent 的 internal/admin 用了 Go1.22 方法路由/PathValue：构建脚本复制 agent-go 到临时目录、go 指令改 1.20、用 `scripts/win7-agent-patch/admin.go` 原地覆盖（行为一致），仓库文件不动
- go-winres 踩坑：comctl32 v6 键名是 `use-common-controls-v6`（写错会被静默忽略 → walk 报 TTM_ADDTOOL failed）；图标只吃 ≤256px PNG 不吃 ico；syso 改动后须重跑 `go-winres make`
- walk API 踩坑：无 TextView（用 TextEdit+SetTextSelection 滚底）；LineEdit 无 Password 字段（SetPasswordMode）；NotifyIcon 无 MouseDoubleClick（用 MouseUp）；图标加载用 png.Decode+NewIconFromImage（LoadIconWithScaleDown 路径会失败）；ListBox 模型必须内嵌 walk.ListModelBase
- 含中文注释的 .ps1 必须存 UTF-8 with BOM（PowerShell 5.1 否则按 ANSI 解析报语法错）
- Trae 沙箱会在命令结束时回收该命令拉起的子进程；需跨命令存活的验证进程用 run_in_background 启动
- gui-walk 与 wails 主 GUI 共享 %ProgramData%\LiYouP2P 配置和单实例互斥体（一方运行时另一方启动会唤起对方并退出）；Win7 版不接自动更新（防误吃 ch=pc 的 wails 升级包）
- Win7 安装器必须双架构通用（2026-11-13 实修）：32 位 Win7 装 amd64 exe 报「此文件的版本与正在运行的 Windows 版本不兼容」；LiLink-win7.iss [Files] 用 `Check: IsWin64`/`not IsWin64` 各嵌一套 exe（DestName 同名），一个安装包 32/64 位通吃

## 平台端功能优化规则
- 平台端所有页面必须统一显示账号、租户信息，包括工作台列表、设备管理、成员管理等模块
- 成员管理列表需按租户分组展示，避免不同租户数据混杂混乱
- 设备管理需新增操作系统字段，由 agent 连接平台时自动上报真实系统版本，老数据显示「—」直至设备下次上线
- 无实际业务数据支撑、无客户端上报逻辑的废弃页面（如服务端口页）应直接删除，避免无效僵尸数据展示
- 平台端所有列表分页必须采用后端分页，禁止前端本地分页，提升大数据量下的加载性能与用户体验
- 平台端表格需实现自适应高度，自动填充可视区域，表格内部出现滚动条，分页控件固定在表格底部
- 平台端需移除页脚版权信息，避免冗余内容占用页面空间
- 平台端 UI 需实现左侧菜单边框与顶部栏边框在左上角交汇为连续 L 形线条，消除错位双线，实现顶部区域视觉融合
- 平台端不存在 SQL 注入风险，所有用户可控参数均通过参数化查询传入，无 SQL 字符串拼接逻辑

## 用户可见文案铁律（2026-11-16，详见 skills/08-用户可见文案规范.md）
