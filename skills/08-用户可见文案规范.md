# 用户可见文案规范（升级说明 / 日志 / 界面提示）

> 适用范围：桌面端（gui-wails、gui-walk）、移动端、以及发布版本时填写的「更新说明」。
> 一句话原则：**用户看到的所有文字，都是用业务语言写的结论，不是技术细节。**

## 1. 硬性要求

1. 不出现网址、协议、IP、端口号、令牌、校验值、文件路径、字段名、接口名、命令参数。
   - 反例：`已连接信令通道 ws://jyly8888.gnway.vip:58894/ws`、`校验失败：sha256 不匹配（期望 3f2a…）`、`HTTP 500`、`exec: "liyou-agent.exe": file does not exist`
   - 正例：`已连接到服务器`、`安装包校验未通过，请稍后重试`、`程序文件不完整，请重新安装`
2. 不出现内部角色名/组件名：Agent → 连接程序；信令 → 连接；套接字/子流/候选/打洞 → 直连/线路；token → 登录信息。
3. 面向用户讲述「发生了什么 + 用户该做什么」，不描述实现过程。
4. 更新说明只写用户能感知的变化（修了什么问题、多了什么按钮、体验改善），不写重构、依赖、版本号细节。

## 2. 更新说明（发布版本时）写法

| 不要写 | 要写 |
|---|---|
| 修复 https 隧道 WebSocket 升级头丢失 | 修复部分网络环境下连接不上的问题 |
| 升级 sha256 校验逻辑 | 提升升级过程的安全性 |
| 优化 STUN 探测时机避免 NAT 映射失效 | 提升不同网络环境下的连接成功率 |
| 新增 /api/update/latest 接口 | 新增「检查更新」按钮 |

控制台「版本发布」页的更新说明输入框已内置该提示文案。

## 3. 代码落地位置（已实现）

- `gui-walk/userlog.go`、`gui-wails/userlog.go`
  - `userizeAgentLine(line) (text, keep)`：底层连接程序日志的翻译层
    - `logNoise`：纯内部行（管理通道、STUN 探测、打洞轮次等）直接丢弃
    - `logRules`：技术行 → 业务语言的规则表（连接、端口开通/断开、线路切换等）
    - 兜底脱敏：网址 → 「服务器」，`token=…` 移除，Agent → 连接程序，sha256 → 完整性校验
  - `friendlyErr(msg)` / `userErr(err)`：底层英文错误 → 白话提示（网络、超时、权限、磁盘、文件缺失）
- 两端日志泵（`pumpLogs`）都先过 `userizeAgentLine`，再进用户日志面板；
  程序自身的提示统一用 `userErr(err)`，不再 `%v` 直接拼底层错误。
- 原始技术日志仍保留在文件日志中（如 `%ProgramData%\LiLink\update\update.log`）供支持排查，不进用户面板。

## 4. 自检清单（改文案时逐条过）

- [ ] 这句里有没有 http/https/ws/IP/端口/路径/token/sha256/HTTP 状态码？
- [ ] 有没有 Agent、信令、套接字、打洞、会话 ID 这类内部词？
- [ ] 用户读完知道「出了什么事」和「我该做什么」吗？
- [ ] 同一个提示是否在其他端（wails / walk / 移动端）也应同步改？

## 5. 新增文案的推荐句式

- 成功：`已连接到服务器` / `已开通：本机端口 8080 ↔ 服务器 8080 端口`
- 暂时失败（可重试）：`暂时无法连接服务器，正在重试…`
- 需要用户操作：`登录信息已失效，请重新登录` / `本机端口 8080 无法使用（可能已被其他程序占用），请更换端口`
- 升级相关：`发现新版本 1.2.0，正在后台下载…` / `升级未完成，已恢复为原版本`
