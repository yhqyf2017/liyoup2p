# 07-构建Win7版（gui-walk 双工具链）

Win7 专用薄壳 GUI 的构建流程与踩坑记录。Win7 交付物与主版本（Win10）并存，互不影响。

## 双工具链（关键前提）

| 用途 | 目录 | 版本 |
|---|---|---|
| 主构建（gui-wails / agent-go / platform-go / AAR） | `D:\soft\go` | go1.22.12 |
| Win7 构建（gui-walk + Win7 版 agent） | `D:\soft\go1.20.14` | go1.20.14 |

- **Go 1.21+ 产物不支持 Win7**，Win7 包必须用 1.20.14；主工程 go.mod 声明 1.22，继续用 1.22。
- ⚠️ **血泪教训**：解压 go1.20 zip 时严禁覆盖 `D:\soft\go`（会混入 1.22 残留文件导致 stdlib 编译错乱，症状如 `internal/abi redeclared`）。两套必须各自独立目录；覆盖后修复方式 = 删掉混装目录、从 zip 重新干净解压。
- 下载地址：https://go.dev/dl/go1.20.14.windows-amd64.zip

## 一键构建

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-win7.ps1
```

产物：
- `dist\win7\LiYouP2P-<arch>.exe` / `liyou-agent-<arch>.exe`（amd64+386 中间产物）
- `dist\LiLink-pc-win7-<ver>-x64.zip` / `-x86.zip`（绿色包，exe 名与主包一致：LiYouP2P.exe + liyou-agent.exe）
- `installer\dist\LiLink-Setup-Win7-<ver>.exe`（amd64 安装器；32 位 Win7 分发 x86 zip）

脚本要点（build-win7.ps1）：
1. agent 构建前**复制到 %TEMP%** 并改写 go.mod（删 toolchain 行、go 指令改 1.20），仓库文件不动
2. agent 的 `internal/admin/admin.go` 用了 Go 1.22 方法路由（`"GET /maps"`）+ `r.PathValue`，Go 1.20 编不了 → 用 `scripts/win7-agent-patch/admin.go` 在临时目录**原地覆盖**（行为完全一致：同 API、同 envelope、同日志「管理通道已就绪：http://…（token=…）」，GUI 的 parseAdminReady 依赖此格式）
3. GUI 构建参数：`-trimpath -ldflags "-s -w -H windowsgui -X main.isRelease=true -X main.appVersion=<ver>"`（正式包必须注入 isRelease）
4. 脚本含中文注释，**必须保存为 UTF-8 with BOM**，否则 PowerShell 5.1 按 ANSI 解析直接报语法错

## gui-walk 模块结构（独立 module，go 1.20，不 import 任何 1.22 模块）

```
gui-walk/
├── main.go        # 入口：单实例互斥体 → runUI；内嵌 PNG 图标
├── app.go         # 自 gui-wails/app.go 移植去 wails 化（登录/会话/Agent/热管理/脱敏）
├── ui.go          # declarative 两页式主窗口（登录页↔工作页，Composite 显隐）
├── tray.go        # walk NotifyIcon 托盘
├── autostart.go   # 原样拷贝 gui-wails/autostart.go
├── singleton.go   # CreateMutexW 单实例 + FindWindow 按标题唤回首实例
├── win.go         # Agent 子进程隐藏启动
├── app_test.go    # 纯函数测试（parseAdminReady/normalizeRule/normalizeLocal/脱敏）
├── winres.json    # 图标+manifest 资源描述
└── assets/appicon*.png
```

- 与主 GUI 共享 `%ProgramData%\LiYouP2P\` 配置（gui.json/settings.json），单实例互斥体同名（与 wails 版互斥：一方在跑，另一方启动会唤起对方并退出）
- wails runtime 事件推送 → 改为 App 上的回调（showUI/hideUI/onLogs/onState），ui.go 注册时用 `mw.Synchronize` 包装，任意线程可调
- 不移植：update.go（防误吃 ch=pc 的 wails 更新包）、watchdog/winhook（WebView2 专项）

## go-winres 资源（图标+manifest）

安装（用 1.22 + 国内代理）：`GOPROXY=https://goproxy.cn,direct go install github.com/tc-hib/go-winres@latest`

生成（gui-walk 目录下）：
```
go-winres make --in winres.json --out rsrc --arch=amd64,386
```
生成 `rsrc_windows_amd64.syso` / `rsrc_windows_386.syso`，go build 自动按 GOARCH 选取。改 winres.json 或图标后必须重跑，否则 exe 无 manifest。

winres.json 踩坑：
- comctl32 v6 的键名是 **`"use-common-controls-v6": true`**（写成 `common-controls: "v6"` 会被静默忽略 → exe 无 v6 manifest → walk 创建控件报 `TTM_ADDTOOL failed`）
- 图标只吃 **PNG**（不吃 .ico），单张 ≤256px，建议给 16/32/48/256 四档
- `dpi-awareness: "system"`（Win7 兼容；walk 自带 DPI 缩放）
- `minimum-os: "win7"`
- **`execution-level: "requireAdministrator"`**（2026-11-13 起，主/Win7 两个 GUI 均默认管理员运行，解决「Access is denied」；代价：每次启动弹 UAC，开机自启在 Win7 登录时会弹 UAC、Win10/11 可能拦截自启）。改后须重跑 `go-winres make`

## walk API 踩坑（v0.0.0-20210112085537 实测）

| 想当然 | 实际 |
|---|---|
| `walk.TextView` | **不存在**，只读多行日志用 `TextEdit{ReadOnly:true, VScroll:true}`；滚底用 `SetTextSelection(n,n)+ScrollToCaret()`（n 为 UTF-16 单位数） |
| LineEdit declarative `Password:true` | 无此字段，Create 后调 `edPass.SetPasswordMode(true)` |
| NotifyIcon `MouseDoubleClick()` | 无此事件，用 `MouseUp()` 判 LeftButton |
| `walk.NewIconFromByteArray/NewIconFromFile/NewIconFromResource` | 走 LoadIconWithScaleDown，部分环境直接失败 → **用 `image/png` 解码内嵌 PNG + `walk.NewIconFromImage(im)`**（纯 GDI，最稳） |
| ListBox Model 只实现 ItemCount/Value | 必须内嵌 `walk.ListModelBase`（带事件发布器），否则报 `dataSource must be a slice of struct…`；刷新 = 改 items + `PublishItemsReset()` |
| TableView Model | 需实现 RowCount/Value + 内嵌 `walk.TableModelBase`，刷新后 `PublishRowsReset()` |
| 表格右侧出现空列头 | declarative `TableView{LastColumnStretched: true}` 让末列吃满剩余宽度（原生属性，非手动算宽） |

## 布局铁律（2026-11-13 修错位实战）

1. **主 VBox 里的两个页面 Composite 必须显式给 StretchFactor**（各 1）：walk 对无 stretch 的 child 会平摊多余高度 → 登录页 Grid 的「角色」行被拉出大空白。页面内部再用 VSpacer（登录页表单上下夹持居中）或分组 stretch（工作页 grpRules 5 / 日志 3）吸收弹性空间，保证顶行/按钮行不被拉伸
2. **Grid Columns 数必须与每行控件数一致**：映射输入行曾用 Columns:5 塞 8 个控件（3 标签+3 输入+2 按钮），row-major 自动换行导致标签与输入框错行。正确做法：标签与输入框成对占一行（Columns 6），按钮独立 HBox 行
3. CheckBox 等「窄控件」单独成行时会被 VBox 拉伸/居中 → 包一层 HBox + 尾部 HSpacer 锁左对齐
4. 截图验证：PrintWindow/GetWindowRect+CopyFromScreen 在沙箱下可能失败/截到壁纸，须带 IsWindowVisible 检查并重试；进程保活用「后台命令内 while 进程存在 sleep」模式

## 沙箱/进程管理经验（本机验证时）

- Trae 沙箱在**命令结束时回收该命令拉起的子进程**（GUI/agent 全被杀）。要跨命令存活的进程：用 Shell 工具 `run_in_background: true` 启动，或禁用沙箱
- 后台进程的进程名取自 exe 实际文件名（如 `liyou-agent-amd64`），Get-Process 别查错
- 平台设备在线验证：superadmin 登录（凭据 platform-go/.env）→ `GET /api/devices` 查 device_uid 的 status
- agent 管理通道单测：起 agent 带 `--admin 127.0.0.1:0 --admin-token <hex32>`，从日志解析端口，curl GET/POST/DELETE /maps 带 Bearer

## 安装器（installer/LiLink-win7.iss）

- 拷贝 LiLink.iss 改：版本、OutputBaseFilename=LiLink-Setup-Win7-<ver>、去掉 `ArchitecturesInstallIn64BitMode`
- **双架构通用**：[Files] 内 amd64/386 两套 exe 各带 `Check: IsWin64` / `Check: not IsWin64`，DestName 同为 LiYouP2P.exe/liyou-agent.exe，安装时按系统位数自动选择（2026-11-13 修复：32 位 Win7 装 amd64 报「此文件的版本与正在运行的 Windows 版本不兼容」）
- AppId 与主包一致（用户换装不产生两份）；防火墙 UDP 规则添加/删除逻辑保留
- 工具：`D:\soft\innosetup\ISCC.exe`
