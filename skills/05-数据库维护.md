# 技能：数据库维护（PostgreSQL 远端库）

适用：liyoup2p 库（192.168.5.9:5432）运行数据清理与例行维护。

## 1. 连接方式

本机无 psql/PostgreSQL，用 platform-go 的 pgx 驱动写临时 Go 工具执行（用完即删）：

```powershell
cd D:\dev\liyou\liyoup2p\platform-go
$env:Path = 'D:\soft\go\bin;' + $env:Path; $env:GOTOOLCHAIN='local'
$env:LIYOU_DSN = (Get-Content '.env' | Select-String '^LIYOU_DSN=').Line -replace '^LIYOU_DSN=',''
go run ./cmd/<临时目录名>
```

`.env` 的 `LIYOU_DSN` 即完整连接串（host/port/user/password/dbname）。

## 2. 表分类（哪些能动哪些不能）

| 类别 | 表 | 处理 |
| --- | --- | --- |
| 运行数据（可清） | audit_logs、tunnel_sessions、alerts | 可整表清空 |
| 核心配置（禁动） | tenants、plans、users、device_ports | 保留 |
| 设备（按规则删） | devices | 只留在线 + 今日活跃 |
| 更新通道 | updates（经控制台管理） | 不在此工具范围 |

## 3. 例行清理 SQL（2026-11-06 实测通过）

```sql
-- 清空运行数据
DELETE FROM audit_logs;        -- 实测 1434 行
DELETE FROM tunnel_sessions;   -- 实测 568 行
DELETE FROM alerts;            -- 实测 33 行

-- 设备：保留 status='online' 或 last_online_at 在今天的（字段是 last_online_at，不是 last_seen_at）
DELETE FROM devices
WHERE status <> 'online'
  AND (last_online_at IS NULL OR last_online_at::date <> now()::date);  -- 实测删 25/50

-- 回收空间（VACUUM 不能在事务内，逐表执行）
VACUUM ANALYZE audit_logs;
VACUUM ANALYZE tunnel_sessions;
VACUUM ANALYZE alerts;
VACUUM ANALYZE devices;
```

## 4. 清理后验证清单

```powershell
Get-Process liyou-platform                                   # 平台在
(Invoke-RestMethod 'http://127.0.0.1:8900/api/auth/login' -Method Post -Body (@{username='admin';password='<密码>';tenant='platform'}|ConvertTo-Json -Compress) -ContentType 'application/json').data.access_token  # 登录正常
Invoke-RestMethod 'http://127.0.0.1:8900/api/devices' -Headers @{Authorization='Bearer <token>'}  # 在线设备数
Get-Process liyou-agent | Measure-Object                     # 常驻 agent 进程数
```

## 5. 坑与注意

- **device_uid 与 agent 令牌强绑定**：删掉的设备其常驻 agent（固定 --device-token 启动）重连会被拒（设备不存在 401），必须重注册换新令牌重启 agent；人工用户无影响（重新登录自动重注册）
- 删除前先 `SELECT ... GROUP BY status, last_online_at::date` 打分布快照，明确将删哪些
- 在线状态是 hub 内存 + 库双态：清理时正在连接的设备行 status=online 会被保留，掉线且非今日的才会删
- hub.go 心跳清理窗口 30s，清理操作不影响活跃连接
- VACUUM 用 pgx 直连即可（autocommit），无需 psql
