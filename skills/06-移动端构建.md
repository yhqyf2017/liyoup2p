# 技能：移动端构建（Flutter + gomobile 嵌入栈）

适用：LiLink 安卓 APK 构建；网络栈来自 agent-go 经 gomobile 打包的 AAR。

## 1. 架构要点（决定构建顺序）

- Dart 层不含 WS/信令：`lib/core/p2p_bridge.dart` 仅 MethodChannel 调 Go
- WS 连接/打洞/隧道全在 `agent-go/mobile`（gomobile 导出面）→ **改 Go 网络栈必须先重编 AAR 再打 APK**
- 版本号位置：`mobile/pubspec.yaml` `version: 1.0.2+3`（+后为 build 号，需递增）

## 2. 环境变量（每次新开 shell 都要设）

```powershell
$env:PATH = 'D:\soft\go\bin;D:\Program Files\Java\graalvm-jdk-21.0.7+8.1\bin;' + $env:PATH
$env:ANDROID_HOME = 'D:\Android\sdk'
$env:JAVA_HOME = 'D:\Program Files\Java\graalvm-jdk-21.0.7+8.1'
$env:GOTOOLCHAIN = 'local'          # 防 go 工具链自动切换导致 compile version mismatch
$env:GOPROXY = 'https://goproxy.cn,direct'
```

- Flutter SDK：`D:\flutter`（dart：`D:\flutter\bin\dart.bat`）
- NDK：`D:\Android\sdk\ndk\28.2.13676358`

## 3. 构建流程

```powershell
# ① 编 AAR（Go 栈有改动时）
cd D:\dev\liyou\liyoup2p\agent-go
go run golang.org/x/mobile/cmd/gomobile bind -target=android -androidapi=24 -ldflags='-s -w' -o liyou-stripped.aar ./mobile
Copy-Item liyou-stripped.aar ..\mobile\android\app\libs\liyou.aar -Force

# ② 静态检查（不打 APK 也能做）
cd ..\mobile
D:\flutter\bin\dart.bat analyze lib        # 必须零 issue

# ③ 打 APK
D:\flutter\bin\flutter.bat build apk --release
# 产物：build\app\outputs\flutter-apk\app-release.apk
```

## 4. 发布前核对

1. `libs/liyou.aar` 时间戳晚于最后一次 Go 栈改动（`agent-go/internal/ws/ws.go` 等）
2. AAR 内含 Bearer 鉴权实现（解包查 `libgojni.so` 含 `Authorization` 串）
3. `pubspec.yaml` 版本已 bump
4. APK 产出后上传 android 通道（见技能 04），上传响应的 sha256 与本地实测一致：

```powershell
(Get-FileHash app-release.apk -Algorithm SHA256).Hash.ToLower()
```

## 5. 注意

- `mobile/build/`、`.dart_tool/`、`android/.gradle/` 均为构建中间产物，已 gitignore
- `android/app/libs/liyou.aar` 是构建输入（保留入库）；agent-go 下生成的 `liyou-stripped.aar` 是产物副本（gitignore）
- 界面文件（lib/pages/）与其他任务并行开发时，只动自己负责的 core/ 文件
- 模拟器无 UDP 打洞环境，验证隧道需真机 + 外网
