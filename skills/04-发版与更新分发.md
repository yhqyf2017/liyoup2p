# 技能：发版与更新分发（三端统一版本 + 双通道）

适用：pc / android 双通道发版、平台包分发、版本一致性核对。

## 1. 版本号统一清单（以 1.0.2 为例）

| 端 | 位置 |
| --- | --- |
| GUI | `gui-wails/update.go:25` appVersion 常量 |
| 安装包 | `installer/LiLink.iss` MyAppVersion |
| 移动端 | `mobile/pubspec.yaml` `version: 1.0.2+3`（+后是 build 号，递增） |
| 平台包 | 无内嵌版本，以发布文件名/通道记录为准 |

## 2. 更新通道机制

- 平台内置双通道更新服务，`POST /api/platform/updates`（super_admin，multipart：channel/version/notes/file）上传发布
- 上传时服务端**实算 SHA256** 存库，`GET /api/update/latest?ch=pc|android`（免鉴权）返回 `{version,url,sha256,notes,releasedAt}`
- `url` 为相对路径 `/update/<文件名>`，客户端拼平台基址；文件落 `update/` 目录（运行数据，gitignore）
- 客户端下载后强校验 SHA256（移动端内置纯 Dart 实现；GUI 亦校验）后走 `.old` 备份替换

## 3. 控制台发版操作

1. 浏览器打开控制台 → 超管登录 → 「版本发布」（仅 super_admin 可见）
2. 选渠道（PC/安卓）→ 填版本号 → 填更新说明 → 选文件（exe/zip/apk，≤200MB，前端校验）→ 发布
3. 上传成功展示新 SHA256，双通道卡片自动刷新；也可 curl 验证：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8900/api/update/latest?ch=pc'   # 应返回新 version/sha256
```

## 4. 实测流程（发版必做）

1. 上传后：`latest` 接口 version 与文件一致
2. 旧版本客户端「检查更新」应提示新版本（GUI 看 `%ProgramData%\LiLink\update.log`）
3. 测试上传后**立即用原包恢复**（避免污染通道）——上传测试包 → 验证 → 重传正式包
4. 恢复后核对 sha256 与正式包一致

## 5. 平台包（不走更新通道）

```powershell
# 内容：liyou-platform.exe + start-platform.ps1 + .env.example（占位模板，不含真实凭据）
Compress-Archive -Path liyou-platform.exe,platform-go\start-platform.ps1,platform-go\.env.example `
  -DestinationPath installer\dist\LiLink-platform-1.0.2.zip -Force
```

放置 `installer/dist/` 即可，运维手动解包后按 `.env.example` 填真实凭据再启动。

## 6. 注意

- pc 通道文件类型限 exe/zip；android 限 apk/zip
- 版本比较为 semver 分段数值（`semverGreater`），发版号必须大于线上版本才提示更新
- 覆盖同版本重传会刷新 releasedAt 与 sha256，客户端无更新提示（相等不算新）
